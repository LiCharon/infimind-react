# 法飞飞 AI 产品需求文档

## Executive Summary

法飞飞 AI 是面向企业经营者、HR、法务、律师和商务人员的 AI 法律智能体平台，核心目标是降低企业处理用工风险与商业合同问题的专业门槛、响应成本和协作成本。

当前项目已具备官网展示、产品矩阵展示、行业案例、客户背书、关于页面、商业合同改写试用页、本地合同改写多 Agent 流水线、文件解析和模板知识库检索能力。下一阶段产品以自研 AI 高代码工作流平台作为底层：通过可版本化的流程编排、提示词配置、法律知识库、任务队列、模型网关和结果渲染能力，统一承载商业合同改写、劳动合同分析、劳动仲裁答辩、员工手册诊断、医疗期计算、养老保险测算、灵活就业保险测算等产品矩阵功能。

产品形态从“公开官网 + 单点试用功能”升级为“公开官网 + 邀请码准入 + 登录后完整功能工作台”。未注册访客可浏览品牌、产品、案例和咨询入口；只有持有效邀请码完成注册的用户，才能进入法飞飞完整功能、创建 AI 任务、查看结果和使用后续企业级能力。

平台必须支持真实客户使用场景下的高并发和长任务稳定性。AI 任务应异步化处理，前端以进度流展示任务阶段；系统应具备限流、排队、重试、降级、审计、可观测性和容量扩展能力，避免单个长合同或高峰流量拖垮整体服务。

## Product Scope

### MVP

MVP 目标是把当前商业合同改写试用升级为登录后可用的自研 AI 法律任务，并建立后续产品矩阵扩展所需的平台底座。

- 保留公开官网、首页产品矩阵、行业案例、客户背书、关于页面和咨询入口。
- 新增登录、注册、邀请码校验、退出登录、基础账号状态管理。
- 新增邀请码管理能力，支持运营人员生成、禁用、查询邀请码使用状态。
- 将商业合同改写从“试用页”升级为登录后核心工具，支持文件上传、任务提交、阶段进度、流式结果、复制结果和错误提示。
- 生产路径仅保留自研本地合同改写引擎和后续模型网关，不保留第三方工作流代理。
- 建立统一 AI 高代码工作流框架，至少支持文件解析、结构抽取、知识检索、风险审查、文本生成、结果组装、错误处理和版本记录。
- 建立异步任务模型，支持任务创建、排队、执行、进度事件、结果保存和失败重试。
- 建立基础高并发能力：任务队列、速率限制、会话隔离、健康检查、日志、指标、告警。
- 建立任务中心最小能力：用户可查看最近任务状态、结果和失败原因。

### Growth

Growth 目标是完整实现产品矩阵中的主要法律工具，并沉淀可复用的法律知识库、模板库和规则配置体系。

- 上线劳动合同分析，输出条款完整性、风险等级、修改建议和参考依据。
- 上线劳动仲裁答辩，基于案情、证据、诉求生成风险判断、答辩思路、证据清单和文书草稿。
- 上线员工手册诊断，识别规章制度风险、程序缺陷、内容冲突和修订建议。
- 上线医疗期计算器，基于员工工龄、司龄、病休记录和地区规则输出医疗期计算过程。
- 上线养老保险测算和灵活就业保险测算，输出测算结果、输入假设、政策依据和风险提示。
- 上线产品级额度与限流策略，按用户、企业、邀请码批次或产品权限控制使用量。
- 上线运营后台，支持用户查询、邀请码管理、任务监控、知识库导入、模板版本管理和问题反馈处理。
- 支持更多商业合同类型，包括买卖、租赁、股权转让、经纪合作、广告投放等。

### Vision

Vision 目标是形成企业级 AI 法律工作台。

- 支持企业租户、部门、成员、角色、权限和企业级审计。
- 支持合同版本管理、历史对比、批注、红线修订导出和多人协作。
- 支持企业私有知识库、专属模板库和定制法律规则。
- 支持 API 集成，将法飞飞 AI 能力嵌入企业 OA、合同管理、人事系统和客户内部流程。
- 支持更完善的人工复核、律师协作和交付闭环，但 AI 输出仍不替代正式法律意见。

## User Journeys

### Journey 1: 访客了解产品并获取邀请

1. 访客进入官网首页。
2. 访客查看产品矩阵、行业服务案例、客户背书和团队介绍。
3. 访客点击咨询或申请体验入口。
4. 系统引导访客提交联系方式或添加咨询二维码。
5. 运营人员线下审核后发放邀请码。

### Journey 2: 邀请用户注册并进入完整功能

1. 用户打开注册页。
2. 用户输入邀请码、手机号或邮箱、密码和必要身份信息。
3. 系统校验邀请码是否存在、有效、未过期、未超过使用次数。
4. 注册成功后邀请码绑定用户账号并记录使用审计。
5. 用户登录后进入功能工作台，看到其权限内可用产品。

### Journey 3: 企业法务完成商业合同改写

1. 用户进入商业合同改写工具。
2. 用户上传 PDF、Word、旧版 Word 或合同截图。
3. 用户输入改写目标，或选择“更严谨”“保留结构”“偏向甲方”“正式签署版本”等快捷目标。
4. 系统创建异步 AI 任务并展示排队、解析、结构分析、知识检索、风险审查、合同改写等阶段。
5. 用户实时查看阶段输出。
6. 系统返回风险清单、修改建议、综合评分和最终可复制合同文本。
7. 用户复制结果或在任务中心再次查看。

### Journey 4: HR 使用用工风险工具

1. HR 登录工作台并选择劳动合同分析或员工手册诊断。
2. HR 上传劳动合同或员工手册。
3. 系统识别用工主体、岗位、期限、试用期、薪酬、工时、解除、保密、竞业、奖惩等关键条款。
4. 系统输出风险等级、依据、修改建议和建议文本。
5. HR 将结果交由法务或外部律师复核。

### Journey 5: 企业处理劳动仲裁答辩

1. 用户选择劳动仲裁答辩工具。
2. 用户输入仲裁请求、事实经过、员工信息、争议焦点，并上传证据材料。
3. 系统生成争议要点、证据缺口、风险区间、答辩策略、证据清单和答辩文书草稿。
4. 系统明确提示输出不构成胜诉承诺，需由专业人员复核后提交。

### Journey 6: 运营管理员维护准入与平台运行

1. 管理员登录后台。
2. 管理员生成邀请码批次，设置过期时间、可用次数、产品权限和备注来源。
3. 管理员查看注册转化、任务量、失败率、模型错误、队列堆积和用户反馈。
4. 管理员更新模板、法律规则、工作流版本，并通过灰度发布控制影响范围。

## Domain Requirements

| ID | Requirement |
| --- | --- |
| DR-01 | 所有法律 AI 输出必须标明“仅供参考，不替代律师或专业法律意见”。 |
| DR-02 | 涉及劳动法、社会保险、医疗期、仲裁答辩的结论必须展示适用前提、输入假设和依据来源，不得输出无条件确定性承诺。 |
| DR-03 | 劳动仲裁答辩不得承诺胜诉结果，只能输出风险判断、证据建议、答辩思路和文书草稿。 |
| DR-04 | 合同和用工材料通常包含敏感商业信息、员工个人信息和争议事实，系统必须默认按敏感数据处理。 |
| DR-05 | 法律知识库、合同模板、计算规则和提示词必须具备版本号、生效时间、更新人和回滚能力。 |
| DR-06 | 当规则存在地区差异或政策时间差异时，系统必须提示用户选择地区、时间或适用规则，不能静默套用默认结论。 |
| DR-07 | 高风险结论应提示人工复核，必要时引导用户咨询律师或法务专家。 |

## Innovation Analysis

- 法飞飞 AI 的差异化不在单个聊天入口，而在用工风险和合同处理产品矩阵：用户围绕具体业务问题选择工具，系统输出结构化、可复核、可复制的专业结果。
- 自研 AI 高代码工作流使产品团队可以用版本化配置组合文件解析、规则校验、知识检索、模型调用和结果模板，而不是依赖第三方工作流。
- 邀请码准入让早期客户试点可控，便于限制成本、沉淀高质量反馈、控制法律风险和逐步放量。
- 法律知识库、合同模板库和计算规则库共同形成可复用资产，使多个产品共享底层专业能力。
- 高并发架构把 AI 长任务从同步请求中拆出，降低文件解析、模型调用和长文本生成对 Web 服务可用性的影响。

## Project-Type Requirements

| ID | Requirement |
| --- | --- |
| PTR-01 | 产品为响应式 Web 应用，支持桌面端完整工作流和移动端浏览、注册、咨询、轻量任务查看。 |

| PTR-04 | 前端需要统一渲染标题、列表、表格、风险等级、引用依据、修改建议和最终文本。 |

| PTR-06 | 高代码工作流配置必须可版本化、可回滚、可灰度发布，并记录每次任务使用的工作流版本。 |
| PTR-07 | 静态官网资源应可 CDN 缓存；AI 任务、登录态和文件上传不得依赖浏览器本地存储作为唯一状态源。 |

| ID | Requirement | Acceptance Criteria |
| --- | --- | --- |

## Architecture Direction

目标架构采用“公开官网 + 认证工作台 + AI 任务平台 + 高代码工作流引擎”的分层模型。

### Target Components

- Web 前端：承载官网、登录注册、工作台、产品矩阵、任务创建、进度展示、结果查看和后台管理入口。
- API 网关：统一鉴权、限流、请求路由、错误格式和审计记录。
- 账号与邀请码服务：管理用户、登录态、角色、邀请码、权限和审计。
- 产品任务服务：负责创建任务、校验额度、记录任务状态、返回进度订阅地址和结果查询。
- 文件服务：负责上传、格式校验、病毒/安全扫描、文本解析、临时存储和清理。
- AI 高代码工作流引擎：按产品和版本执行节点，包括解析、抽取、知识检索、规则判断、模型生成、结果组装和错误处理。
- 模型网关：统一封装模型供应商、超时、重试、并发限制、成本统计和降级策略。
- 知识库服务：管理合同模板、劳动法规则、社保规则、员工手册规范、行业条款和检索索引。
- 任务队列与工作器：承载长任务排队、并发控制、重试、取消和失败恢复。
- 运营后台：管理邀请码、用户、任务、工作流版本、知识库版本、反馈和运行指标。

### 本地自研引擎方向

- 生产目标路径不得依赖第三方工作流代理。
- 当前代码路径仅保留本地合同改写引擎，默认端口为 8789。
- 前端不再暴露多引擎切换；用户只感知法飞飞统一 AI 能力。
- 新功能必须接入自研任务平台和高代码工作流引擎。

### High-Concurrency Approach

- Web/API 服务保持无状态，支持多实例水平扩展。
- AI 长任务进入队列，由工作器按产品、用户、模型和资源类型限制并发。
- 前端通过任务 ID 订阅进度；断线后可重新查询任务状态。
- 队列积压时返回预计等待或限流提示。
- 模板、规则和轻量结果可缓存；敏感原文不得进入无权限共享缓存。
- 文件解析、知识检索和模型调用分阶段记录耗时，便于定位瓶颈。
- 健康检查区分进程存活、依赖可用、队列可消费、模型网关可用。

## Testing Strategy

| Area | Coverage |
| --- | --- |
| 认证与邀请码 | 邀请码有效、过期、禁用、重复使用、权限绑定、登录、退出、未授权访问、管理员权限。 |
| 商业合同改写 | 文件上传、格式限制、部分解析失败、全部解析失败、任务排队、阶段进度、风险输出、最终文本、复制结果。 |
| 产品矩阵工具 | 劳动合同分析、仲裁答辩、员工手册诊断、医疗期计算、养老保险测算、灵活就业保险测算的核心输入输出路径。 |
| 高代码工作流 | 工作流版本、节点失败、重试、灰度发布、回滚、知识库版本绑定、模型网关错误。 |
| 异步任务 | 创建任务、查询状态、订阅进度、断线恢复、取消任务、失败重试、任务历史。 |
| 高并发压测 | 登录会话、任务提交、队列堆积、长任务执行、限流、背压、服务扩容后的吞吐变化。 |
| 安全 | 未登录访问、越权访问、管理员 API、敏感配置暴露、日志敏感信息、上传文件访问权限。 |
| 知识库 | 模板导入、规则导入、版本更新、检索命中、无命中兜底、回滚。 |
| 前端体验 | 桌面端和移动端导航、注册登录、工作台、任务页、结果页、错误态、空状态、二维码咨询。 |
| 构建与发布 | 生产构建、环境变量缺失、健康检查、灰度发布、回滚流程。 |

常规 CI 不应依赖真实模型供应商。模型调用、文件解析和知识检索应支持 mock 或测试替身；真实模型链路作为可选集成测试和上线前验收。

## Out of Scope

- 当前阶段不实现套餐计费、在线支付、发票、订单和商业化结算。
- 当前阶段不实现移动端原生 App 或小程序。
- 当前阶段不承诺 AI 输出可直接替代律师正式法律意见或对仲裁、诉讼结果作保证。
- MVP 不实现完整拖拽式无代码工作流设计器；高代码工作流可先通过配置文件、后台表单或工程化配置管理。
- MVP 不实现完整企业租户、部门、复杂 RBAC 和 SSO；这些进入 Vision 阶段。
- MVP 不实现电子签章、法院/仲裁委在线提交、正式律师函代发。
- MVP 不实现复杂合同红线对比和 Word 修订模式导出；可复制文本和结构化报告优先。
- 当前 PRD 不选择具体云厂商、数据库、中间件或模型供应商；架构文档负责落地技术选型。
